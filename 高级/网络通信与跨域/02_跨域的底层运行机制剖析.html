02_跨域时，请求到底发出去没有？

💡 核心真相与底层运行流水线：

很多开发者误以为：控制台报 CORS 错误 = 请求在前端就被阻止了，压根没发出去。

真实情况完全相反：

  1. 阶段 1（发送阶段）：浏览器完全放行，HTTP 请求正常顺着网线飞往后端服务器；
  2. 阶段 2（服务端处理）：后端服务器正常接收并解析了请求，甚至执行了数据库写入或业务计算；
  3. 阶段 3（服务端返回）：后端将执行结果和数据包封装成 HTTP 响应，传回浏览器；
  4. 阶段 4（浏览器拦截）💥：当数据刚到达浏览器入口时，浏览器“同源策略检查员”查看响应头，发现没有 Access-Control-Allow-Origin 通行证，当场将响应数据扣押并销毁，并向前端控制台抛出 CORS 红色错误！

⚠️ 为什么 <img>、<script> 不会跨域，只有 Ajax / fetch 会跨域？

同源策略主要限制的是 【JavaScript 脚本通过代码读取外部资源的数据】：

  • <img src="https://other.com/a.jpg">：虽然从外部下载了图片并展示，但 JS 脚本无法直接读取到图片的内部像素二进制数据，所以允许。
  • <script src="https://cdn.com/vue.js">：虽然下载了外部脚本，但浏览器只负责执行它，并不存在跨域读取隐私数据的危险，所以允许（这也是当年 JSONP 的原理来源！）。
  • fetch('https://other.com/api')：JS 试图直接把返回的 JSON 数据装进变量里读取，存在偷窃隐私和资金安全的风险，被浏览器严厉拦截！

# 04. Point-Free 风格与方法引用（Point-Free & Method References）

> 本文深入剖析函数式编程中的 Point-Free 风格，以及为什么 `arr.map(Number)` 能成功，而 `arr.map(parseInt)` 会惨遭翻车。

---

## 一、 什么是 Point-Free 风格？

* **学术名称**：**Eta 转换（Eta Reduction）** / 无参风格（Tacit Programming）；
* **在其他语言中的对应物**：
  * **Java 8+**：方法引用（`Integer::parseInt`）
  * **Python**：直接传递函数对象（`map(int, list)`）
* **核心哲学**：  
  **“不要显式地声明无意义的数据参数名（Point / Argument），只关注函数本身作为管道的对接。”**

---

## 二、 4 步推导演进：为什么能干掉中间商？

以“把数字字符串转为真正数字”为例：

```javascript
// 阶段 1：普通函数定义
function parseItem(item) {
  return Number(item);
}
arr.map(parseItem);

// 阶段 2：ES5 匿名函数
arr.map(function(item) {
  return Number(item);
});

// 阶段 3：ES6 Lambda 箭头函数
arr.map(item => Number(item));

// 阶段 4：Point-Free 风格（消去多余的中间商）
arr.map(Number);
```

### 为什么能从“阶段 3”跳到“阶段 4”？
仔细观察阶段 3：
```text
item => Number(item)
 ↑              ↑
 输入进来        原封不动转交给 Number
```
外层的箭头函数除了把 `item` 原封不动塞给 `Number` 之外，**什么多余的事情都没干**。既然它只是个无意义的传话筒，直接把最终干活的工具 `Number` 本身递给 `map`，完全等价！

## 三、 慢动作拆解：arr.map(Number) 的底层全流程

```text
               ┌──────────────────────────────┐
               │    ['1', '2', '3'] 数组       │
               └──────────────┬───────────────┘
                              │
                    调用 .map( Number )
                              │
    ┌─────────────────────────┴─────────────────────────┐
    │ map 开启底层内部循环 for (let i = 0; i < 3; i++)   │
    └─────────────────────────┬─────────────────────────┘
                              │
     ┌────────────────────────┼────────────────────────┐
     ▼                        ▼                        ▼
【第 1 轮：i = 0】        【第 2 轮：i = 1】        【第 3 轮：i = 2】
调用: Number('1', 0, arr) 调用: Number('2', 1, arr) 调用: Number('3', 2, arr)
     │                        │                        │
  Number 只收第1个         Number 只收第1个         Number 只收第1个
  后面的全自动忽略         后面的全自动忽略         后面的全自动忽略
     │                        │                        │
  得到数字: 1              得到数字: 2              得到数字: 3
     │                        │                        │
     └────────────────────────┼────────────────────────┘
                              │
                              ▼
               ┌──────────────────────────────┐
               │  打包生成新数组: [1, 2, 3]    │
               └──────────────────────────────┘
```

## 四、 深度对比：为什么 Number 成了，而 parseInt 翻车了？

| 对比维度 | `['1', '2', '3'].map(Number)` (成功 💯) | `['1', '2', '3'].map(parseInt)` (翻车 ❌) |
| :--- | :--- | :--- |
| **底层被调用的函数原型** | `Number(value)` | `parseInt(string, radix)` |
| **该函数能吃几个参数？** | **只能吃 1 个参数**（后面的无视） | **能吃 2 个参数**（第 2 个参数是数学进制！） |
| **第 1 轮循环 (index=0)**| `Number('1', 0)` ➔ 忽略 0 ➔ 得 `1` | `parseInt('1', 0)` ➔ 0 被当成默认 10 进制 ➔ 得 `1` |
| **第 2 轮循环 (index=1)**| `Number('2', 1)` ➔ 忽略 1 ➔ 得 `2` | `parseInt('2', 1)` ➔ **按 1 进制解析 '2'** ➔ 非法进制，得 `NaN`！ |
| **第 3 轮循环 (index=2)**| `Number('3', 2)` ➔ 忽略 2 ➔ 得 `3` | `parseInt('3', 2)` ➔ **按二进制解析 '3'** ➔ 二进制无 3，得 `NaN`！ |
| **最终输出结果** | **`[1, 2, 3]` (完美)** | **`[1, NaN, NaN]` (灾难)** |

## 五、 黄金法则：什么时候能简写？什么时候严禁简写？

### ✅ 适用场景（目标函数只在乎 1 个参数）：
```javascript
// 1. 转数字：
['1', '2', '3'].map(Number); // [1, 2, 3]

// 2. 转字符串：
[1, 2, 3].map(String); // ['1', '2', '3']

// 3. 过滤所有假值（0, false, '', null, undefined）：
[0, 1, false, 2, '', 3].filter(Boolean); // [1, 2, 3] (大厂神级优雅写法！)
```

### ❌ 严禁简写场景（目标函数有第 2 个敏感可选参数）：
```javascript
// ❌ 翻车陷阱：
['1', '2', '3'].map(parseInt);

// ✅ 必须显式写箭头，把参数隔离开：
['1', '2', '3'].map(item => parseInt(item, 10));
```

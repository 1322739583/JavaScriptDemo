# 01. 纯函数与副作用（Pure Function & Side Effects）

> 纯函数是整个函数式编程最基础、最重要的“第一块基石”。

---

## 一、 什么是纯函数？

一个函数若要被称为**“纯函数”**，必须同时满足以下两个铁律条件：

1. **相同的输入，永远产生绝对相同的输出**（确定性 / 引用透明性 Referential Transparency）；
2. **执行过程中没有任何“副作用”（No Side Effects）**，不改变外部世界的状态。

```javascript
// ✅ 纯函数：无论调用一万次，只要传入 2 和 3，结果必定是 5，且外界没有任何变化
function add(a, b) {
  return a + b;
}
```

---

## 二、 什么是“副作用（Side Effects）”？

所谓副作用，是指函数在执行计算返回结果之外，**暗中对宿主环境或外部状态造成了改动**。

常见的副作用操作包括：
* 修改了全局变量或闭包外部的变量；
* 修改了传入的参数对象（修改了原数据）；
* 执行了 I/O 操作（写本地磁盘、读写 LocalStorage）；
* 发送了网络请求（`fetch` / `axios`）；
* 触发了 DOM 操作；
* 调用了生成随机数的 `Math.random()`，或者获取当前时间的 `Date.now()`（因为相同输入无法保证相同输出）。

### 经典对比示例

```javascript
// ❌ 非纯函数（依赖并修改外部变量）
let discount = 0.8;
function calculatePrice(price) {
  return price * discount; // discount 可能在外部随时被改变，导致输出不确定
}

// ❌ 非纯函数（产生副作用：修改了原参数！）
function addItem(cart, item) {
  cart.push(item); // 致命！修改了外部传入的 cart 数组原引用！
  return cart;
}

// ✅ 改造为纯函数（遵循不可变原则）
function addItemPure(cart, item) {
  return [...cart, item]; // 返回全新数组，原数组毫发无伤！
}
```

## 三、 为什么 React 和 Redux 强推纯函数？

1. **React 官方组件规范**：
   * React 官方文档第一条哲学：*“All React components must act like pure functions with respect to their props.”*（所有 React 组件必须像纯函数一样保护其 props 不被篡改）。
2. **时间旅行与状态快照（Time Travel Debugging）**：
   * Redux 的 `reducer(state, action)` 必须是绝对纯函数。只有保证纯函数，前端工具才能实现撤销、重做、状态时空回溯回放。
3. **缓存优化（Memoization）**：
   * 只有纯函数才能做计算缓存（如 `useMemo`、`React.memo`）。因为对于相同的入参，直接从缓存哈希表中读取结果返回即可，无需重复执行昂贵的计算。

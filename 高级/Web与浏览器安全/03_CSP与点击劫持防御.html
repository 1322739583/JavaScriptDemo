03_CSP 内容安全策略与点击劫持（Clickjacking）

一、CSP（Content-Security-Policy 内容安全策略）

本质：由服务端通过 HTTP 响应头告诉浏览器的一份【资源访问白名单】。

即使网页被注入了恶意脚本，由于 CSP 的限制，浏览器也会拒绝下载恶意外部代码，或拒绝向恶意外部域名回传数据！

常见配置示例：

# 只能加载本域的资源，图片可以从本域和 cdn.example.com 加载：
Content-Security-Policy: default-src 'self'; img-src 'self' https://cdn.example.com;

# 彻底禁止任何内联脚本（如 <script>alert(1)</script> 或 onclick 事件）：
Content-Security-Policy: script-src 'self';

二、点击劫持（Clickjacking / UI 覆盖攻击）

攻击方式：黑客搭建一个诱人的网页（如“免费领 iPhone”），但在网页上层用一个完全透明的 <iframe> 覆盖了你正常的银行或微博页面。

当你以为自己在点击“领奖”按钮时，实际上你的鼠标点在了下层透明 iframe 里的“确认转账”或“一键关注”按钮上！

防御手段：

  • HTTP 响应头：X-Frame-Options
    • DENY：绝对禁止任何页面通过 iframe 嵌套本网页；
    • SAMEORIGIN（常用）：只允许同源的页面通过 iframe 嵌套；
  • 现代 CSP 指令：frame-ancestors 'self'。

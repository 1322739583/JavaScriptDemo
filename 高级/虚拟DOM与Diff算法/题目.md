# 虚拟 DOM 与 Diff 算法经典面试题（纯题目版）

> **自测指南**：
> 尝试在脑海中组织答题框架或进行口述，重点考察核心概念辨析、业务场景 Bug 推演以及算法思想的表达。
> 思考完成后，对照 [答案.md](./答案.md) 进行核对与查漏补缺。

### 题目一：什么是虚拟 DOM？为什么现代前端框架（Vue / React）要引入虚拟 DOM？它一定比直接操作真实 DOM 快吗？
* **考察维度**：对虚拟 DOM 本质的理解与常见性能误区的辨析。
* **思考提示**：
  * 虚拟 DOM 在内存中的物理形态是什么？
  * “虚拟 DOM 一定比真实 DOM 快”这个说法正确吗？为什么？
  * 引入虚拟 DOM 带来的三大真正核心价值是什么？

---

### 题目二：在 `v-for` 列表渲染中，为什么推荐使用唯一的 `id`，而强烈不推荐使用 `index` 作 `key`？
* **考察维度**：Diff 算法比对机制与真实业务渲染事故推演（中级绝对必考）。
* **思考提示**：
  * 框架判定两个节点是“同一个节点（可以复用）”的依据是什么？
  * 如果列表项带有输入框（如 `<input>`）或复选框，在列表头部插入新数据时，用 `index` 会产生什么灵异的界面 Bug？
  * 从性能角度来看，用 `index` 和用 `id` 在 DOM 操作次数上有什么巨大差距？

---

### 题目三：在什么特殊情况下，允许使用 `index` 作为 `key`？
* **考察维度**：对规则边界的理解，避免死记硬背教条。
* **思考提示**：
  * 必须同时满足哪三个苛刻条件，使用 `index` 才不会引发 Bug 和性能倒退？

---

### 题目四：传统的树比对算法复杂度是 $O(n^3)$，现代前端框架的 Diff 算法是如何做到将其优化为 $O(n)$ 线性级别的？
* **考察维度**：数据结构与算法优化策略。
* **思考提示**：
  * 框架在比对时采用了哪三大“启发式假设（策略）”？
  * 跨层级的 DOM 节点移动框架是怎么处理的？
  * 节点标签名改变时框架是怎么处理的？
  * 列表兄弟节点的复用依赖什么机制？

# 为什么隔壁Java一年一更，JavaScript却为了ES6整整憋了6年？聊聊前端那段魔幻的“黑历史”

> **作者寄语**：我们在写现代前端（Vue 3、React、Vite）时，对 `let/const`、`import/export` 早就习以为常。但如果你翻看 2015 年以前的老开源代码，几乎每个文件的首尾都被一段长相极其古怪的代码统治：`(function(){ ... })()`。  
> 为什么当年的前端开发者要捏着鼻子写这种“反直觉”的丑陋代码？为什么在移动互联网已经如日中天的 2015 年，JavaScript 才终于定稿了 ES6？中间隔了那么多版本，官方都在干嘛？  
> 今天，我们就扒一扒前端发展史上最精彩、最魔幻的一段“血泪史”。

---

## 一、一切的原罪：1995 年那仓促的 10 天

要弄明白 JavaScript 为什么有这么多“设计缺陷”，必须回到一切的起点——1995 年 5 月。

当时正处于第一次浏览器大战前夜，网景公司（Netscape）急需一款能在浏览器里运行的脚本语言来抗衡微软。管理层给工程师**布兰登·艾克（Brendan Eich）**下达了死命令：**10 天内搞定。**

在极度紧迫的工期下，布兰登做出了一系列妥协设计：
1. **没有模块系统**：所有脚本默认共享同一个全局对象（浏览器里的 `window`）。
2. **没有块级作用域**：`{}` 只是个摆设，只有函数能圈出作用域。
3. **只有 `var`**：不仅可以重复声明，还会发生诡异的“变量提升（Hoisting）”。

在当年，大家觉得完全无所谓：“这只是一个在浏览器里做做鼠标悬浮变色、弹个 `alert('欢迎光临')`、验证一下表单的玩具语言，撑死写 30 行代码，要什么模块化和块级作用域？”

可谁也没想到，这个“临时小玩具”，日后竟长成了支撑起万亿级互联网大厦的参天巨树。

---

## 二、历史的真相：中间根本没有那么多版本！

初学前端的朋友常常会有个直觉：“从 ES1 一路排到 ES6，中间隔了 ES2、ES3、ES4、ES5，这么多版本难道就没人顺手把它改了吗？”

**真实的历史令人大跌眼镜：在长达 16 年里，JavaScript 几乎只经历了一次真正的小修补。**

### 1. ES2（1998年）：纯盖章文件，新功能为 0
ES1 刚发布一年后就推出了 ES2。但它**一行新语法都没加**，纯粹是为了配合国际标准化组织（ISO/IEC 16262）的格式规范，做了一次文档排版校对。

### 2. ES3（1999年）：当时的人根本没有这个痛点
ES3 带来了正则表达式、`try/catch` 等语法，奠定了我们熟悉的基础语法。但在 1999 年，网页上的 JS 代码依旧少得可怜，全世界没有任何一个人觉得“缺少模块化”是个问题。

### 3. ES4（2000~2008年）：步子迈太大，扯崩了！
到了 2005 年，**Google Maps** 和 **Gmail** 横空出世，彻底颠覆了全球认知——原来在网页里能做出媲美桌面客户端的超大型单页应用（Web 2.0 时代到来）！

前端代码量瞬间从几十行暴增到几万行甚至几十万行。TC39 委员会如梦初醒，开始疯狂起草 **ES4**。
那 ES4 到底修没修模块化和作用域？**不仅修了，而且修疯了！**

当时的激进派（Mozilla、Adobe）试图一步到位，把 JS 改造成跟 Java、C++ 一样强大的工业级语言：加入了强类型系统、类、接口、命名空间、包（Packages/Modules）……

**结果引发了技术史上著名的“委员会大内讧”：**
- **保守派（微软、Yahoo 的 Douglas Crockford）**强烈反对，认为这会把轻量级脚本语言搞得比 Java 还臃肿复杂，性能和实现难度谁来买单？
- **商业算盘**：微软靠 IE6 垄断了 90% 以上的市场，巴不得 Web 越烂越好，好推自家垄断的 Windows 桌面应用和 Silverlight。

**两派在委员会里撕逼、内讧整整吵了 8 年。最终在 2008 年，官方正式宣布：ES4 彻底破产夭折，全部心血付之一炬！**

### 4. ES5（2009年）：“劫后余生”的妥协小补丁
ES4 搞崩后，大家痛定思痛，决定先搞一个折中妥协版——这就是 2009 年发布的 **ES5**。
为了让各厂商（尤其是顽固的微软 IE）痛快落地，ES5 **严格禁止加入任何改变底层语法结构的改动**：
- 没有 `let/const`（底层作用域链改动太大）；
- 没有原生模块化（争议巨大，继续搁置）；
- 仅仅增加了 `Object.defineProperty`、严格模式 `'use strict'` 和一些数组高阶方法。

而真正涉及语言骨骼重塑的大招（`let/const`、`import/export`、类、箭头函数），被打包封存，起了一个富有戏剧性的代号——**“Harmony（和谐计划）”**。

这一“和谐”，又是整整 6 年。

## 三、民间的绝望救赎：IIFE 的悲壮诞生

在官方迟迟交不出模块化和块级作用域的那些年，全世界的前端工程师快被逼疯了。

一个大型项目里几十个 JS 文件，只要两个文件同时写了 `var user = 'xxx'`，变量就会毫无预警地在全局被覆盖，整个程序莫名其妙崩溃。

**既然语言官方不给块级作用域，而整个 JS 唯一能产生独立局部作用域的只有“函数”，开发者们只能被逼着“戴着镣铐跳舞”——发明了 IIFE（Immediately Invoked Function Expression，立即执行函数表达式）。**

```javascript
// 📦 经典的 IIFE 沙箱模式（也是当年 jQuery、Lodash 的标准骨架）：
(function (window) {
  var privateData = "秘密数据"; // 关在函数闭包里，绝不污染全局！
  
  // 只向全局暴露一个受控的命名空间
  window.myLib = {
    getData: function() { return privateData; }
  };
})(window);
```

### 为什么必须在外层加一对括号？（语句 vs 表达式）
这也是很多新手的疑惑：为什么非要写成 `(function(){ ... })()` 这么古怪？直接写 `function(){ ... }()` 不行吗？

因为在 JavaScript 引擎中存在一个硬性规定：
- 只要开头的第一个单词是 `function`，引擎就会判定这是一条**【函数声明语句（Statement）】**。语句是不能加括号执行的（就像你不能写 `if(true){}()` 一样荒谬）；
- **而在数学和 JS 中，小括号 `( ... )` 是“分组运算符”，里面强制只能放【表达式（Expression）】**；
- 一旦把 `function` 包在括号里，引擎就被迫把它解析成一个能求出值的**“函数表达式”**，表达式的返回值就是这个函数本身；
- 紧随其后的调用括号 `()`，就能立刻把这个刚出炉的函数执行掉！

> **IIFE 就像是用胶带（Duct Tape）去缠一根漏水的大水管。**  
> 每一个写下 `(function(){})()` 的开发者都知道它很丑陋、很别扭，但在官方修好水管之前，若不用这层胶带，整座业务大厦就会被变量污染的洪水冲垮。

## 四、为什么发一个 ES6 整整憋了 6 年？隔壁 Java 一年一更！

到了 2015 年，移动互联网、4G、微信、各种 App 都已经如火如荼了，为什么制定一个 ES6 需要整整 6 年（2009~2015）？这帮人拖延症这么严重吗？

其实，背后有三条比拖延症残酷一百倍的客观枷锁：

### 1. 隔壁 Java 当年也没好到哪去
大家今天看到的“Java 一年一个版本”，是 2017 年 Java 9 之后才改的制度。在 2015 年前，Java 也是个“难产大户”：
- **Java 6 到 Java 7**：整整憋了 **5 年**（2006 ~ 2011）；
- **Java 7 到 Java 8**（引入 Lambda）：又憋了 **近 4 年**（2011 ~ 2014）。

更关键的是：**Java 是甲骨文（Oracle）一家独大说了算，老板拍板就能发版。而 JavaScript 面临的是“神仙打架”。**

### 2. TC39 委员会：各怀鬼胎的“联合国安理会”
坐在这张规范制定会议桌前的，不是同事，而是当时在商场上杀得刺刀见红的死对头：
- **苹果 Apple（Safari）**：靠 App Store 躺着抽 30%“苹果税”。如果 Web 性能和开发体验太强大，大家都去写网页应用了，谁还下原生 App？因此苹果在很长一段时间里对 Web 新标准抱持极度保守消极的阻挠态度。
- **谷歌 Google（Chrome）**：靠搜索和网页广告起家，最恨原生 App 这种信息孤岛，巴不得把整个操作系统搬进 Chrome 浏览器，是激进推新派。
- **微软 Microsoft**：守着 Windows 桌面和 IE 烂摊子，一度在移动时代梦游。

在全员拥有一票否决权的委员会里，要让竞争对手们就每一个关键字的底层逻辑达成全票共识，难度堪比让安理会五常在所有议题上全员举手赞成。

### 3. 悬在头顶的死咒：“绝不能搞崩现有的 Web（Don't break the web）”
像 Python 这种语言，觉得老版本太烂，大不了推出 Python 3（直接破坏向后兼容）。结果全网经历了大迁徙的剧烈阵痛，足足耗费了 14 年才平息。

**但 JavaScript 绝对没有“不向后兼容”的特权！**
> 世界上没有任何人有权力跑到全球几十亿台手机电脑上，把历史老网站删掉重编。  
> 委员会铁律：**1995 年写下的一段上古 JS 网页，在 2026 年最新版的 Chrome 里跑，必须完好无损！**

新语法决不能搞挂任何老网页。在不能动老地基的前提下平地起摩天大楼，推演验证极其艰巨。

### 4. ES6 根本不是“升级”，而是一场彻底的“推倒重构”
平心而论，这 6 年憋出来的 ES6，堪称**软件工程史上最大规模的单次语言进化**。我们今天写前端代码用到的几乎所有现代化语法，全是当年 ES6 这一次性倾泻出来的：
- **`let` / `const`**（彻底干翻 `var`，确立词法块级作用域）
- **ES Module**（`import / export`，彻底终结 IIFE 时代）
- **Promise**（现代异步编程基石，消灭回调地狱）
- **箭头函数 `() => {}`**（彻底干翻恶心的 `var self = this`）
- **Class 与类继承**（告别晦涩的原型链写法）
- **Proxy 与 Reflect**（没有它，就没有今天的 **Vue 3 响应式系统**！）
- **解构赋值、模板字符串、展开运算符 `...`、Map/Set/Symbol**

这相当于**在一辆跑在高速公路上的破拖拉机上，不熄火、不减速，硬生生把它原地改装成了一台高铁！**

---

## 五、亡羊补牢：终于学乖了

被 ES6 这次“6 年大难产”险些搞崩生态后，TC39 委员会痛定思痛，彻底废除了以前“好几年憋一次大招”的做派，改为了现代化的**流水线提案制（Stage 0 ~ Stage 4）**：
- **成熟一个就发布一个**；
- **每年固定发一个版（以年号命名）**：ES2016、ES2017（加入 `async/await`）、ES2020（加入可选链 `?.`）……

从此，JavaScript 的迭代速度才真正像坐上了火箭。

---

## 结语

今天我们回望 IIFE，觉得它又怪异又丑陋，甚至有人称它为“烂代码”。

但事实上，**它正是那一代前端先驱们，在长达 16 年的技术荒原与黑暗中，用智慧和胶水死死撑起 Web 繁荣的最强铁证。**

了解这段历史，不仅能让我们在读到老库源码时不至于两眼一抹黑，更能让我们在今天随手敲出 `const` 和 `import` 时，体会到现代 Web 工程化走过这段泥泞岁月的不易。

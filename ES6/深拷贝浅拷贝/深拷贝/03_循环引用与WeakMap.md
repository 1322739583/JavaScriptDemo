# 循环引用与 WeakMap 的高级作用

在深拷贝中，**循环引用**（对象嵌套自己，如 `obj.loop = obj`）是一个致命问题。

## 1. Node.js 控制台的保护机制
如果你用 Node.js 的 `console.log` 打印包含循环引用的对象，你会看到类似 `<ref *1>` 和 `[Circular *1]` 这样的标记。
* `<ref *1>`：用来给最外层对象贴个标签（当作锚点）。
* `[Circular *1]`：告诉开发者“这里的属性指向了刚刚贴标签的那个外部对象”。
如果不这样拦截，控制台打印时就会陷入“无限套娃”的死循环，直到内存溢出崩溃。

## 2. WeakMap 在深拷贝里的双重使命
传统的 `JSON.parse(JSON.stringify())` 遇到循环引用会直接抛错。为了解决这个问题，手写深拷贝时我们会引入一个 `WeakMap` 当作“克隆登记册”：

```javascript
if (weakMap.has(target)) {
  return weakMap.get(target); // 登记过，直接拿走，打破死循环
}
weakMap.set(target, cloneTarget); // 登记在案
```

它其实承担了**两项**极其重要的使命：
1. **保命（防死循环）**：解决真正的循环引用问题，打破无限递归。
2. **保真（维护共享引用）**：就算没有循环，只是原对象的两个属性共同指向了同一个嵌套子对象（共享内存地址），`WeakMap` 也能识别出来，直接将这个子对象克隆一次复用，**从而完美保留了原始数据结构的网络拓扑关系**。如果没有它，这两个属性在拷贝后就会指向两个互相独立的克隆体，破坏了原始的“共享”语义。

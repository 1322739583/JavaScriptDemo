# 数组的本质剖析

在 JavaScript 中，**数组并不是独立的基本数据类型**。在宏观层面上，它隶属于引用数据类型中的 `Object`。

## 1. 数组就是一种“特殊的对象”
如果你用 `typeof [1, 2, 3]` 测试，会返回 `"object"`。
在 JS 引擎眼中，普通对象是字符串到值的映射，而数组是一种将**键名强制设定为“从 0 递增的字符串”**的特殊对象。
```javascript
// [ "a", "b" ] 在底层类似于：
{
  "0": "a",
  "1": "b",
  "length": 2
}
```

## 2. 数组的“特权”
虽然本质是对象，但引擎给了数组很多普通对象没有的优待：
* **动态的 length 属性**：往里面加东西 length 会自动变大；手动改小 length 会自动截断数组。
* **专属的原型链**：普通对象原型是 `Object.prototype`，数组的原型是 `Array.prototype`。这让数组天生自带 `.map()`, `.filter()`, `.forEach()` 等海量方法。
* **底层的内存优化**：在 V8 等现代引擎中，如果数组装的是相同类型的纯粹数据，引擎会抛弃哈希表，改用连续内存的 C/C++ 级底层数组结构来存储，极大提升遍历性能。

## 3. 判断数组的三种正确姿势
既然 `typeof []` 是 `"object"`，我们该如何判断它？
1. **`Array.isArray(arr)`**：（⭐ 最推荐，ES5标准，无视 iframe 跨域问题）
2. **`Object.prototype.toString.call(arr)`**：（万能法，返回 `"[object Array]"`)
3. **`arr instanceof Array`**：（有缺陷，如果对象跨 iframe 窗口传递，由于构造函数不共用，会导致判定失败）

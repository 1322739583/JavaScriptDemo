# JavaScript 数组练习题 参考答案

---

### 第 1 题
* **直接修改原数组**：`push()`、`pop()`、`shift()`、`unshift()`、`splice()`、`sort()`、`reverse()`
* **不修改原数组（纯函数，返回新数据）**：`slice()`、`concat()`、`map()`、`filter()`、`reduce()`

---

### 第 2 题
* **原因**：React 等框架依赖**浅比较（`Object.is`）**检测状态变更。直接调用 `list.push()` 或 `list.reverse()` 属于原位修改，**数组在堆内存中的引用地址未发生改变**（`prev === next` 为 true），导致框架误判状态未更新，从而跳过组件重新渲染。
* **正确写法**：必须产生新的数组引用：
  ```javascript
  setList([...list, newItem]);
  setList([...list].reverse());
  ```

---

### 第 3 题
ES2023（ES14）新增了 4 个绝不改变原数组的不可变操作方法：
1. `arr.toSorted()` ➔ 对应传统 `sort()`
2. `arr.toReversed()` ➔ 对应传统 `reverse()`
3. `arr.toSpliced()` ➔ 对应传统 `splice()`
4. `arr.with(index, value)` ➔ 对应传统不可变替换 `arr[i] = val`

---

### 第 4 题
* **返回值**：
  * `push()` / `unshift()`：返回插入元素后，数组的**新长度 `length`（数字）**。
  * `pop()` / `shift()`：返回**被移除的元素本身**（若数组为空则返回 `undefined`）。
* **设计哲学**：
  * 弹出操作属于数据消费，如果不返回该项，数据将在内存中丢失；
  * 插入操作时，传入的元素本身已被调用者持有，返回元素毫无新增信息量，此时返回当前容器的“新容量深度（length）”提供了唯一的信息增益。

---

### 第 5 题
* **`slice(start, end)`**：
  * **含义**：只读切片。从 `start` 坐标截取到 `end` 坐标（左闭右开 `[start, end)`）。
  * **返回值**：截取出的新数组。
  * **对原数组影响**：**完全不修改原数组**。
* **`splice(start, count, ...items)`**：
  * **含义**：剪接手术。从 `start` 开始，切除 `count` 个元素，并把后续的 `...items` 缝合进断口处。
  * **返回值**：被切除的元素组成的新数组（相当于剪切板）。
  * **对原数组影响**：**直接就地修改原数组**。

---

### 第 6 题
* **定义**：拥有非负整数 `length` 属性，且能通过数字下标（`0, 1...`）访问属性的普通对象。原型为 `Object.prototype`，不具备数组原型方法。
* **转换方式**：
  * `Array.from(likeArray)`：最宽容，只要有 `length` 属性即可转换，即使没有部署迭代器协议也能成功；
  * `[...likeArray]`：必须要求对象部署了迭代器协议 `[Symbol.iterator]`。纯手写的类数组 `{ length: 2 }` 使用 `[...likeArray]` 会抛出 `TypeError: object is not iterable`。

---

### 第 7 题
* **演进顺序**：
  1. 传统下标 `for (let i = 0; i < arr.length; i++)`（1995，最快但繁琐）；
  2. `for...in`（1995，原本为对象设计）；
  3. `arr.forEach()`（2009 ES5，函数式，不可中途 break）；
  4. `for...of`（2015 ES6，终极形态，兼具简洁与随时 break）；
  5. `for await...of`（2018 ES9，异步流迭代）。
* **极不推荐对数组使用 `for...in` 的原因**：
  1. 拿到的索引是**字符串类型**（`"0"`, `"1"`），做加法会变成字符串拼接；
  2. 会沿原型链遍历出**自定义扩展属性与原型污染**；
  3. 不保证按数字递增顺序遍历。

---

### 第 8 题
* **能否 `break`**：**绝对不能**。在 `forEach` 里写 `break` 会报语法错误；写 `return` 也只是提前结束当前这一次回调函数的执行（相当于 `continue`），依然会继续遍历后面的项。
* **执行 `await` 的现象**：`forEach` 内部不会等待异步 Promise 决议，会导致所有的异步操作**不受控地瞬间并发乱跑**，外部同步代码会早于异步操作提前执行，造成执行时序混乱。

---

### 第 9 题
* **标准写法**：
  ```javascript
  for (const [index, item] of arr.entries()) { ... }
  ```
* **为什么是 `[index, item]`**：因为在全世界的计算机数据结构中，永远遵循 **`Key-Value Pair（键值对）`** 规范（键在前，值在后）。在数组中，索引下标是 Key，元素是 Value。
* **`arr.entries()` 返回的具体是什么**：返回一个 **`Array Iterator（数组迭代器对象）`**。它采用**惰性求值**，循环每前进一步才临时计算吐出一项，极度节省内存，绝不是预先生成一个巨大的二维数组。

---

### 第 10 题
* **输出**：`[1, NaN, NaN]`
* **原因**：`map` 传给回调的是 `(item, index, array)`，而 `parseInt` 接收的是 `(string, radix)`。导致 `index` 被作为进制基数传递：
  * 第 1 轮：`parseInt('1', 0)` ➔ 进制为 0 默认按 10 进制解析 ➔ `1`；
  * 第 2 轮：`parseInt('2', 1)` ➔ 不存在 1 进制，参数非法 ➔ `NaN`；
  * 第 3 轮：`parseInt('3', 2)` ➔ 二进制只认 0 和 1，字符 `'3'` 非法 ➔ `NaN`。

---

### 第 11 题
* **输出**：
  ```javascript
  [ <3 empty items> ]
  3
  false
  ```
* **原因**：`new Array(3)` 创建的是带有 3 个空洞（empty）的稀疏数组。`map()` 在执行时会依据规范**主动跳过所有空洞**，回调函数一次都不会被调用，因此空洞被原样保留；`'0' in arr` 检测是否存在该属性，返回 `false`。

---

### 第 12 题
* **输出**：`[10, 20, 3, 5]`
* **原因**：`sort()` 默认不传参时，**会将所有元素转为字符串，按照 UTF-16 字典码点顺序排序**。字符 `'1'` 排在 `'2'` 前面，`'2'` 排在 `'3'` 前面，故 `"10"`、`"20"` 优先排在前面。若按数字大小升序排必须显式传入：`nums.sort((a, b) => a - b)`。

---

### 第 13 题
* **输出**：
  ```javascript
  3
  undefined
  false
  ```
* **原因**：`delete` 只负责删除对象本身的属性键，**不会重新排列数组，也不会缩容 `length`**；索引 1 的位置变成了空洞，用下标读取时虽然表现为 `undefined`，但底层并不存在该键名，因此 `1 in list` 返回 `false`。

---

### 第 14 题
* **输出**：
  ```javascript
  undefined
  'c'
  ```
* **原因**：在 JavaScript 中数组本质是对象，方括号 `arr[-1]` 是属性访问器语法，引擎会查找名为 `"-1"` 的字符串属性（未找到返回 `undefined`）。若强行修改方括号行为会让老旧网站发生 Breaking Change，因此 ES2022 专门推出了 `at(-1)` 原生支持负数倒数索引。

---

### 第 15 题
* **`resA`**：`false`
* **`resB`**：`true`
* **原因（假值陷阱）**：
  * `arr.find(x => x === 0)` 成功找到了元素，并把元素本身（数字 `0`）返回了。然而在 JS 中 `Boolean(0)` 的结果是 `false`，导致误判为未找到；
  * `arr.some(x => x === 0)` 返回纯粹的逻辑真假判定，不受元素自身假值的影响，稳定返回 `true`。

---

### 第 16 题
* **判定规则**：对数组每一项执行判定，**必须全员通过才返回 `true`**；只要遇到任何一项返回 false，立刻短路停下并返回 `false`。
* **业务场景**：
  * 电商购物车底部的“全选”按钮联动：
    ```javascript
    const isAllChecked = cart.every(item => item.checked);
    ```
  * 多个表单输入框的提交前校验：
    ```javascript
    const canSubmit = formFields.every(field => field.isValid);
    ```

---

### 第 17 题
* **输出**：
  ```javascript
  false
  true
  ```
* **原因**：
  * 空数组没有任何元素，`some` 无法抓出任何一个满足项，返回 `false`；
  * `every` 在数学逻辑上遵循**“空真假说（Vacuous Truth）”**：因为在空集合中根本找不出任何一个违背条件的成员，故判定为全体通过，返回 `true`。

---

### 第 18 题
* **`arr.map()`**：是数组原型上的**动词方法**，用于对数组元素进行一对一的加工转换，输入 N 个元素输出 N 个元素的新数组；
* **`new Map()`**：是 ES6 引入的**名词数据结构（字典容器）**，用于存储 Key-Value 键值对，其最大特性是支持任意类型（包括对象、DOM 节点、函数）作为键。

---

### 第 19 题
* **`arr.length`**：`10001`
* **V8 内部变化**：
  * 执行前：准备按连续线性内存开辟空间的**快数组（Fast Elements）**；
  * 执行后：下标跨度过大产生了巨大的空间空洞，为了避免极端浪费物理内存，V8 瞬间将该数组**降级为哈希字典模式的「慢数组（Dictionary Elements）」**。

---

### 第 20 题
* **快数组**：物理内存连续分配的线性列表，直接根据内存地址偏移取值，读写速度极快（$O(1)$）；
* **慢数组**：底层蜕变为哈希表字典，索引变成字符串键，每次查找需先进行哈希运算与冲突比对，性能明显下降；
* **为什么慎用 `delete arr[i]`**：`delete` 会在原连续内存中打出一个空洞，强行打破连续内存布局，促使 V8 将数组由快数组降级为慢数组，产生难以逆转的性能惩罚。

### 第 21 题
```javascript
Array.prototype.myFlat = function (depth = 1) {
  if (depth <= 0) return this.slice();

  return this.reduce((acc, cur) => {
    if (Array.isArray(cur)) {
      return acc.concat(cur.myFlat(depth - 1));
    } else {
      return acc.concat(cur);
    }
  }, []);
};
```

### 第 22 题
1. **为什么 `new Set(cart)` 无法去重**：
   * `Set` 去重依赖内部的 `SameValueZero` 规则（类似 `===`）；
   * 即使两个对象字面量长得完全一样（如 `{ id: 101, ... }`），它们在堆内存中的**引用地址不同**，`objA === objB` 依然为 `false`，因此 `Set` 无法对引用类型对象去重。
2. **$O(N)$ 极速去重代码**：
   ```javascript
   function uniqueById(list) {
     const seenIds = new Set();
     return list.filter(item => {
       if (seenIds.has(item.id)) {
         return false;
       }
       seenIds.add(item.id);
       return true;
     });
   }
   ```
